Nivel 0 · Básico

Qué es un CHECK y dónde se escribe

Una restricción CHECK es una regla que tiene que cumplir cada fila de una tabla. MySQL la comprueba cada vez que se guarda una fila: en INSERT, UPDATE, REPLACE y LOAD DATA. Si la regla da falso, la operación falla.

Versión: MySQL aplica los CHECK desde la 8.0.16. En versiones anteriores la sintaxis se acepta, pero se ignora sin avisar. Compruébalo con SELECT VERSION();

Sintaxis

[CONSTRAINT [nombre]] CHECK (expresión) [[NOT] ENFORCED]

Se puede escribir en dos sitios:

TipoDónde vaQué columnas puede usar
De columnadentro de la definición de una columnasolo esa columna
De tablaseparada por comas, junto a las columnas (normalmente al final)cualquier columna de la tabla
CREATE TABLE producto (
  id      INT AUTO_INCREMENT PRIMARY KEY,
  nombre  VARCHAR(50) NOT NULL,
  precio  DECIMAL(8,2) CHECK (precio > 0),                       -- de columna, sin nombre
  stock   INT CONSTRAINT prod_stock_ck CHECK (stock >= 0),     -- de columna, con nombre
  CONSTRAINT prod_nombre_ck CHECK (CHAR_LENGTH(nombre) >= 2)   -- de tabla, con nombre
);

Nombres

Si no le pones nombre, MySQL lo genera: tabla_chk_1, tabla_chk_2… en el orden en que aparecen. Ponles nombre siempre (por ejemplo tabla_columna_ck): el error dice qué restricción ha fallado y luego la puedes desactivar o borrar por su nombre. Los nombres de CHECK no se pueden repetir en toda la base de datos, ni siquiera en tablas distintas.

Cuando una fila no cumple

ERROR 3819 (HY000): Check constraint 'prod_stock_ck' is violated.

Una regla importante que verás a fondo en el nivel 2: el CHECK solo rechaza la fila cuando la expresión da FALSE. Si da TRUE o NULL, la fila entra.

Los textos y la colación

MySQL compara los textos según la colación de la columna. La de MySQL 8 por defecto es utf8mb4_0900_ai_ci: ai = no distingue acentos, ci = no distingue mayúsculas. Por eso 'tarde' = 'TARDE' y 'Manana' = 'MAÑANA' son verdaderas.

Para listas cerradas de textos MySQL tiene también el tipo ENUM('MAÑANA','TARDE'). Con CHECK la regla queda a la vista y se puede combinar con otras columnas.

Nivel 2 · Básico

NULL y la lógica de tres valores

En SQL una condición puede valer TRUE, FALSE o NULL (desconocido). Cualquier comparación con un NULL da NULL: NULL > 0, NULL = NULL y NULL <> 'A' valen NULL.

La regla clave: un CHECK solo rechaza la fila si la condición da FALSE. Con TRUE o con NULL, la fila entra.
ABA AND BA OR B
TRUENULLNULLTRUE
FALSENULLFALSENULL
NULLNULLNULLNULL

Y NOT aplicado a NULL sigue siendo NULL.

  • Para preguntar por NULL se usa IS NULL o IS NOT NULL, que siempre dan TRUE o FALSE. Nunca = NULL.
  • MySQL tiene además <=>, la igualdad segura con NULL: NULL <=> NULL es TRUE.
  • Si una columna es obligatoria, lo correcto es NOT NULL en la columna (error 1048, más claro). Un CHECK con IS NOT NULL también lo consigue.
  • Nunca pongas NULL dentro de NOT IN (…): la condición pasa a valer NULL para cualquier valor que no esté en la lista.
Nivel 3 · Intermedio

Reglas entre varias columnas

Un CHECK de tabla puede comparar columnas entre sí y hacer operaciones con ellas: fecha_fin >= fecha_inicio, adultos + ninos <= plazas. La regla se evalúa con los valores de la misma fila.

Un CHECK de columna solo puede usar su propia columna. Si en la definición de a escribes CHECK (a > b), MySQL no crea la tabla. Escríbelo como restricción de tabla; ahí sí puedes usar columnas que se definen más abajo.

En las columnas opcionales, la lógica de tres valores trabaja a tu favor: precio_oferta < precio_venta se cumple o se ignora sola cuando no hay oferta.

Nivel 4 · Intermedio

Reglas condicionales: «si… entonces…»

Muchas reglas de negocio son condicionales. Así se traducen:

ReglaCondición
Si A, entonces BNOT A OR B
A si y solo si B(A AND B) OR (NOT A AND NOT B)
Al menos uno de x, yx IS NOT NULL OR y IS NOT NULL
Exactamente uno de x, y(x IS NULL) XOR (y IS NULL)
Según el valor de una columnaCASE tipo WHEN 'A' THEN … WHEN 'B' THEN … ELSE FALSE END

Ejemplo: «si el estado es BAJA, hay fecha de baja» se escribe estado <> 'BAJA' OR fecha_baja IS NOT NULL.

Cuidado con NULL en la parte del «si»: si A puede ser NULL, NOT A OR B puede dar NULL y dejar pasar la fila. Por eso en estos ejercicios la columna de la condición es NOT NULL.

Mayúsculas y minúsculas

Con la colación por defecto (…_ci), 'Madrid' = 'MADRID' es verdadero. Por eso provincia = UPPER(provincia) no obliga a escribir en mayúsculas: siempre se cumple. Para comparar distinguiendo mayúsculas:

  • provincia COLLATE utf8mb4_bin = UPPER(provincia)
  • CAST(provincia AS BINARY) = UPPER(provincia)
  • REGEXP_LIKE(provincia, '^[A-ZÑ ]+$', 'c'): la 'c' hace que distinga mayúsculas.
  • Declarar la columna con COLLATE utf8mb4_bin.

Lo mismo pasa con LIKE e IN: con la colación por defecto no distinguen mayúsculas ni tildes.

Nivel 7 · Avanzado

Lo que un CHECK no puede hacer

Según el manual de MySQL, la expresión de un CHECK solo puede usar literales, columnas de la propia tabla, operadores y funciones deterministas (las que con los mismos datos dan siempre el mismo resultado). Está prohibido:

  • Funciones no deterministas: NOW(), CURDATE(), CURRENT_DATE, RAND(), UUID(), CURRENT_USER(), CONNECTION_ID()…
  • Funciones almacenadas (las creadas con CREATE FUNCTION).
  • Variables de usuario (@x), del sistema (@@x) o de procedimientos.
  • Subconsultas y columnas de otras tablas.
  • Columnas AUTO_INCREMENT.
  • Columnas que usa una clave ajena con ON UPDATE u ON DELETE.

Nivel 8 · Avanzado

Gestionar restricciones con ALTER TABLE

-- Añadir
ALTER TABLE producto ADD CONSTRAINT prod_precio_ck CHECK (precio > 0);

-- Desactivar y volver a activar (se conserva la definición)
ALTER TABLE producto ALTER CHECK prod_precio_ck NOT ENFORCED;
ALTER TABLE producto ALTER CHECK prod_precio_ck ENFORCED;

-- Borrar (DROP CONSTRAINT también funciona desde MySQL 8.0.19)
ALTER TABLE producto DROP CHECK prod_precio_ck;

-- Ver cómo ha quedado
SHOW CREATE TABLE producto;
  • Al añadir una restricción activa o al pasarla a ENFORCED, MySQL comprueba las filas que ya hay. Si alguna la incumple, la sentencia falla con el error 3819 y no cambia nada. Corrige o borra antes esas filas.
  • Una restricción NOT ENFORCED existe, pero no se comprueba.
  • Un CHECK no se modifica: para cambiar la condición, se borra y se vuelve a crear. Se puede hacer en una sola sentencia: ALTER TABLE t DROP CHECK x, ADD CONSTRAINT x CHECK (…);
  • Con INSERT IGNORE o UPDATE IGNORE, las filas que incumplen un CHECK se saltan con un aviso en vez de un error.

Consultar las restricciones

SELECT tc.TABLE_NAME, tc.CONSTRAINT_NAME, tc.ENFORCED, cc.CHECK_CLAUSE
FROM information_schema.TABLE_CONSTRAINTS tc
JOIN information_schema.CHECK_CONSTRAINTS cc
  ON cc.CONSTRAINT_SCHEMA = tc.CONSTRAINT_SCHEMA
 AND cc.CONSTRAINT_NAME = tc.CONSTRAINT_NAME
WHERE tc.CONSTRAINT_TYPE = 'CHECK'
  AND tc.TABLE_SCHEMA = DATABASE();

En los ejercicios de este nivel puedes escribir varias sentencias separadas por ;: ALTER TABLE, INSERT, UPDATE, DELETE, SELECT * FROM y SHOW CREATE TABLE.

Nivel 9 · Experto

Diseñar una tabla completa

Ahora escribes el CREATE TABLE entero: columnas, tipos, NOT NULL, clave primaria y todas las restricciones. Los INSERT de prueba se ejecutan en orden sobre tu tabla, así que también cuentan las claves repetidas.

Un método que funciona:

  • Lee cada requisito y decide si es tipo de dato, NOT NULL, DEFAULT, clave o CHECK.
  • Escribe un CHECK con nombre por cada regla. Es más fácil saber cuál falla.
  • Para cada regla, piensa en un valor válido, uno inválido y NULL.
  • Repasa los textos (mayúsculas, espacios, LENGTH frente a CHAR_LENGTH) y las fechas.
