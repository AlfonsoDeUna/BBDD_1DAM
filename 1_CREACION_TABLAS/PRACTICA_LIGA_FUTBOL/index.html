Paso 3 · Interpretar los símbolos

¿Qué cardinalidad tiene la relación?

Leyenda de cardinalidades

Junto a EQUIPO

|| Uno y solo uno

Cada jugador pertenece a un único equipo.

Junto a JUGADOR

○< Cero o muchos

Un equipo puede tener varios jugadores (o ninguno todavía en la base de datos).

Conclusión: relación 1:N entre equipo y jugador. ¿En qué tabla se coloca la FK?

Paso 4 · Autocorrección

Comprueba y corrige tu código SQL

Compara estas soluciones con tus CREATE TABLE. Revisa especialmente la PK, la FK y los tipos de datos.

Solución · EQUIPO
CREATE TABLE equipo (
  id_equipo INT PRIMARY KEY,
  goles_a_favor INT,
  goles_en_contra INT,
  disparos_a_puerta INT,
  faltas INT,
  tarjetas_amarillas INT,
  tarjetas_rojas INT
);

ALTER TABLE equipo
ADD CONSTRAINT chk_equipo_goles
CHECK (goles_a_favor >= 0);
Solución · JUGADOR
CREATE TABLE jugador (
  id INT PRIMARY KEY,
  nombre VARCHAR(100),
  id_equipo INT,
  goles INT,
  partidos_jugados INT,
  goles_por_partido DECIMAL(5,2),
  FOREIGN KEY (id_equipo)
    REFERENCES equipo(id_equipo)
);

ALTER TABLE jugador
ADD CONSTRAINT chk_jugador_partidos
CHECK (partidos_jugados >= 0);

Los dos CHECK son ejemplos. Si has elegido otros que tienen sentido y funcionan, también son correctos. Orden: crea primero equipo y después jugador.

Prompt A

Pide las 20 filas con goles a favor y en contra, disparos a puerta, faltas y tarjetas.

Prompt B

Datos de JUGADOR

Pide todos los jugadores, sus goles, partidos y promedio, recorriendo las páginas.

Antes de ejecutar: comprueba la temporada, que los id_equipo coincidan y que la IA no invente registros. Inserta primero los equipos y después los jugadores.
