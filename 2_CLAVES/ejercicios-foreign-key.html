Un ejemplo antes de empezar

Primero el padre; después, la hija con su FK.

CREATE TABLE categorias (
    id_categoria INT PRIMARY KEY
);

CREATE TABLE productos (
    id_producto INT PRIMARY KEY,
    id_categoria INT NOT NULL,
    CONSTRAINT fk_productos_categoria
        FOREIGN KEY (id_categoria)
        REFERENCES categorias(id_categoria)
);

CONSTRAINT da nombre a la restricción. También puedes omitirlo y escribir directamente FOREIGN KEY (...) REFERENCES tabla(columna).

Ejercicio 01

Clientes y pedidos

clientes ya existe. Crea pedidos con su PK y una FK sin nombre explícito. Cada pedido debe tener un cliente.

clientes

PKid_clienteINT
nombreVARCHAR(100)
1N

pedidos

PKid_pedidoINT
FKid_clienteINT · NOT NULL

Un cliente puede tener varios pedidos.

SQL de partida · Tablas ya disponibles
CREATE TABLE clientes (
    id_cliente INT PRIMARY KEY,
    nombre VARCHAR(100)
);
PK · FK obligatoria · FOREIGN KEY y REFERENCES.
Ver una posible solución
CREATE TABLE pedidos (
    id_pedido INT PRIMARY KEY,
    id_cliente INT NOT NULL,
    FOREIGN KEY (id_cliente)
        REFERENCES clientes(id_cliente)
);

Ejercicio 02

Departamentos y empleados

departamentos ya existe. Crea empleados y nombra la FK fk_empleados_departamento. Todo empleado debe tener departamento.

departamentos

PKid_departamentoINT
1N

empleados

PKid_empleadoINT
nombreVARCHAR(100)
FKid_departamentoINT · NOT NULL

El departamento puede repetirse en empleados.

SQL de partida · Tablas ya disponibles
CREATE TABLE departamentos (
    id_departamento INT PRIMARY KEY
);
PK · CONSTRAINT con el nombre indicado · FK obligatoria.
Ver una posible solución
CREATE TABLE empleados (
    id_empleado INT PRIMARY KEY,
    nombre VARCHAR(100),
    id_departamento INT NOT NULL,
    CONSTRAINT fk_empleados_departamento
        FOREIGN KEY (id_departamento)
        REFERENCES departamentos(id_departamento)
);

Ejercicio 03

Editoriales y libros

editoriales ya existe. Crea libros. Puede haber libros pendientes de editorial, por lo que su FK debe admitir NULL. Nombra la FK fk_libros_editorial.

editoriales

PKid_editorialINT
1N

libros

PKid_libroINT
tituloVARCHAR(150)
FKid_editorialINT · admite NULL

Un libro sin editorial usa NULL, no un identificador inventado.

SQL de partida · Tablas ya disponibles
CREATE TABLE editoriales (
    id_editorial INT PRIMARY KEY
);
PK · FK opcional · mismo tipo que la PK referenciada.
Ver una posible solución
CREATE TABLE libros (
    id_libro INT PRIMARY KEY,
    titulo VARCHAR(150),
    id_editorial INT NULL,
    CONSTRAINT fk_libros_editorial
        FOREIGN KEY (id_editorial)
        REFERENCES editoriales(id_editorial)
);
