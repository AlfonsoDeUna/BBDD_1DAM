Construye tus propias relaciones

Siete ejercicios breves para aplicar PK, FK, AUTO_INCREMENT, CONSTRAINT y reglas de integridad referencial. Puedes consultar las páginas anteriores.

Tu trabajo: escribe los SQL en tu editor MySQL. Se indican los campos y requisitos; debes decidir cómo declararlos. Cada ejercicio usa tablas distintas y se realizará en una misma base de datos vacía.

1 puntos

Ejercicio 01

Una tabla con clave primaria

Un centro necesita registrar sus salas.

salas

id_sala INT

nombre VARCHAR(60)

  • Crea la tabla con id_sala como PK en la propia columna.
  • El identificador se introducirá manualmente: no uses AUTO_INCREMENT. El nombre es obligatorio.
1 puntos

Ejercicio 02

Un identificador automático

El centro también registra su material.

materiales

id_material INT

descripcion VARCHAR(100)

  • Haz que id_material se genere con AUTO_INCREMENT.
  • Declara la PK como restricción de tabla utilizando CONSTRAINT. La descripción es obligatoria.
2 puntos

Ejercicio 03

Una relación 1:N y una FK añadida después

Un proyecto puede tener varias tareas. Cada tarea pertenece obligatoriamente a un solo proyecto.

proyectos

id_proyecto INT

titulo VARCHAR(100)

tareas

id_tarea INT

descripcion VARCHAR(120)

id_proyecto INT

  • Crea ambas tablas, cada una con su PK. Título y descripción son obligatorios.
  • Crea tareas inicialmente sin la restricción FK. Añádela después con ALTER TABLE y ADD CONSTRAINT, con un nombre que elijas.
  • Impide borrar un proyecto que tenga tareas. Si cambia su identificador, actualiza automáticamente la FK de sus tareas.
1,5 puntos

Ejercicio 04

Conservar registros al borrar el padre

Una revista puede tener varias noticias. Una noticia puede estar pendiente de revista.

revistas

id_revista INT

nombre VARCHAR(80)

noticias

id_noticia INT

titular VARCHAR(150)

id_revista INT

  • Crea las dos tablas con sus PK; nombre y titular son obligatorios.
  • Declara la FK con CONSTRAINT dentro de CREATE TABLE. Debe admitir que una noticia no tenga revista.
  • Si se borra una revista, conserva sus noticias y deja la referencia a NULL. Si cambia su identificador, propaga el cambio.
1,5 puntos

Ejercicio 05

Una PK compuesta y borrado en cascada

Cada albarán tiene líneas numeradas. El mismo número de línea puede aparecer en distintos albaranes, pero no repetirse dentro del mismo.

albaranes

id_albaran INT

fecha DATE

lineas_albaran

id_albaran INT

num_linea INT

concepto VARCHAR(100)

  • Crea la PK de albaranes sobre id_albaran. La fecha es obligatoria.
  • En lineas_albaran declara una PK compuesta con id_albaran y num_linea. El concepto es obligatorio.
  • Relaciona las líneas con su albarán mediante una FK con nombre.
  • Al borrar un albarán, borra sus líneas. Al cambiar su identificador, actualiza sus referencias.
1,5 puntos

Ejercicio 06

Resuelve una relación N:M

Un deportista puede participar en varias pruebas. En cada prueba pueden participar varios deportistas.

deportistas

id_deportista INT

nombre VARCHAR(100)

pruebas

id_prueba INT

nombre VARCHAR(80)

  • Crea las dos tablas con sus PK y nombres obligatorios.
  • Diseña y crea una tabla intermedia, con un nombre que elijas y solo los dos identificadores necesarios.
  • Declara las dos FK con nombre y evita registrar dos veces la misma pareja deportista + prueba mediante una PK compuesta.
  • Si se borra un deportista o una prueba, borra sus participaciones. Los cambios de sus identificadores deben propagarse.
1,5 puntos

Ejercicio 07

Limita una relación a 1:1

Cada socio puede tener como máximo un carné. Cada carné pertenece obligatoriamente a un socio.

socios

id_socio INT

nombre VARCHAR(100)

carnes

id_carne INT

id_socio INT

  • Crea ambas tablas con sus PK. El nombre del socio es obligatorio.
  • En carnes, declara id_socio como FK obligatoria y añade UNIQUE para impedir dos carnés del mismo socio.
  • Al borrar un socio, elimina su carné. Al cambiar su identificador, propaga el cambio.
  • La relación puede permitir socios sin carné; no es necesario obligar a crear uno para cada socio.

Condiciones de entrega

  1. Entrega un único archivo SQL llamado actividad_claves_nombre_apellidos.sql, con los siete ejercicios.
  2. Incluye al principio un comentario con tu nombre, apellidos, grupo y fecha. Separa y numera cada ejercicio con comentarios.
  3. El archivo debe poder ejecutarse completo, en orden, en una base de datos vacía ya seleccionada. Crea las tablas padre antes que las hijas y coloca cada ALTER TABLE después de la tabla que modifica.
  4. Entrega únicamente el código SQL final necesario para los ejercicios, sin soluciones alternativas duplicadas ni capturas de pantalla.
  5. En esta actividad no se piden INSERT, SELECT, DELETE ni UPDATE de datos: debes definir las tablas, restricciones y acciones ON DELETE / ON UPDATE.
  6. Comprueba en MySQL que el archivo se ejecuta sin errores antes de entregarlo. Usa tipos compatibles y nombres claros para las restricciones.
¿Qué se evalúa? Que cada ejercicio cumpla sus requisitos: campos y tipos, PK, obligatoriedad de los datos, FK, cardinalidad y acciones referenciales. La puntuación aparece en cada enunciado y suma 10 puntos.
