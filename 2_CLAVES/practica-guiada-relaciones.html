Bases de datos · Relaciones 1:N

Relacionar dos tablas con SQL

Lee cada paso, copia el código en tu gestor de bases de datos y responde a las preguntas.

1. ¿Qué queremos guardar?

Una biblioteca quiere registrar sus estanterías y los libros que tiene en ellas.

Una estantería puede contener varios libros. Cada libro está colocado en una sola estantería.

Esta es una relación uno a muchos (1:N).

Vamos a guardar estos datos:

Estanterías

id_estanterianombre
1Ciencia
2Literatura
3Historia

Libros

id_librotituloid_estanteria
101El universo1
102El cuerpo humano1
103Cuentos del bosque2
Observa y responde
  1. ¿Qué libros están en la estantería Ciencia?
  2. ¿Hay alguna estantería sin libros?
  3. ¿Qué campo de la tabla de libros permite conocer la estantería de cada libro?

2. Crear la primera tabla: la clave primaria

Copia y ejecuta:

CREATE TABLE Estanteria (
    id_estanteria INT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL
);

PRIMARY KEY indica la clave primaria, también llamada PK. Es el campo que identifica de forma única cada fila.

En esta tabla, cada estantería tiene un identificador diferente. Una clave primaria no puede repetirse ni contener un valor nulo.

NOT NULL indica que el campo no puede contener un valor nulo, es decir, no podemos dejarlo sin un valor.

Ahora añade las estanterías. Copia y ejecuta:

INSERT INTO Estanteria (id_estanteria, nombre)
VALUES (1, 'Ciencia');

INSERT INTO Estanteria (id_estanteria, nombre)
VALUES (2, 'Literatura');

INSERT INTO Estanteria (id_estanteria, nombre)
VALUES (3, 'Historia');

INSERT INTO permite añadir una fila a una tabla. Los valores de VALUES corresponden, en el mismo orden, a los campos indicados.

Consulta los datos:

SELECT * FROM Estanteria;

SELECT * muestra todas las columnas de la tabla.

Comprueba: deben aparecer las tres estanterías del apartado 1.

Observa y responde
  1. ¿Cuál es la clave primaria de Estanteria?
  2. ¿Podrían existir dos estanterías con el mismo identificador?
  3. ¿Impide esta definición que dos estanterías tengan el mismo nombre?

3. Crear la segunda tabla: la clave foránea

Copia y ejecuta:

CREATE TABLE Libro (
    id_libro INT PRIMARY KEY,
    titulo VARCHAR(100) NOT NULL,
    id_estanteria INT NOT NULL,
    FOREIGN KEY (id_estanteria)
        REFERENCES Estanteria(id_estanteria)
);

Esta tabla tiene dos campos con funciones diferentes:

  • id_libro es la clave primaria (PK) de Libro. Identifica cada libro.
  • id_estanteria es una clave foránea (FK), también llamada clave ajena. Relaciona cada libro con una estantería existente.

Esta parte del código establece la relación:

FOREIGN KEY (id_estanteria)
    REFERENCES Estanteria(id_estanteria)

Significa que el valor de Libro.id_estanteria debe existir en Estanteria.id_estanteria.

Por ejemplo, para guardar un libro en la estantería 1, debe existir previamente una estantería con ese identificador.

Además, hemos declarado Libro.id_estanteria con NOT NULL, por lo que no podemos dejar un libro sin estantería.

Observa y responde
  1. ¿Puede haber varios libros con el mismo id_estanteria?
  2. ¿Puede haber varios libros con el mismo id_libro?
  3. ¿Por qué hemos creado primero la tabla Estanteria?

4. Introducir los libros y observar la relación

Copia y ejecuta:

INSERT INTO Libro (id_libro, titulo, id_estanteria)
VALUES (101, 'El universo', 1);

INSERT INTO Libro (id_libro, titulo, id_estanteria)
VALUES (102, 'El cuerpo humano', 1);

INSERT INTO Libro (id_libro, titulo, id_estanteria)
VALUES (103, 'Cuentos del bosque', 2);

Consulta los datos:

SELECT * FROM Libro;

Comprueba: deben aparecer los tres libros del apartado 1.

Los dos primeros libros tienen el valor 1 en id_estanteria. Esto es correcto: varios libros pueden pertenecer a la misma estantería.

En una relación 1:N, la clave foránea se coloca en la tabla del lado «muchos». En este ejemplo, se coloca en Libro.

El campo id_estanteria es clave primaria en Estanteria y clave foránea en Libro. Su función depende de la tabla en la que se encuentre.

Observa y responde
  1. ¿Cuántos libros tiene la estantería 1?
  2. ¿Qué valor de id_estanteria corresponde a Historia?
  3. ¿Por qué no necesitamos guardar el nombre de la estantería en cada libro?

5. Comprobar qué permite la base de datos

Ejecuta las siguientes pruebas una por una y una sola vez. Algunas están preparadas para producir un error.

Antes de ejecutar cada prueba, escribe qué crees que ocurrirá. Después, observa el resultado y responde.

Prueba A. Otro libro en la misma estantería

Observa y responde

  2. ¿Puede repetirse el valor 1 en la clave foránea de varios libros?

Prueba C. Una estantería que no existe

Prueba D. Un libro sin estantería

INSERT INTO Libro (id_libro, titulo, id_estanteria)

Observa y responde

  2. ¿Qué parte de la definición de id_estanteria impide guardar un valor nulo?

Comprobar los datos después de las pruebas

Copia y ejecuta:

Comprueba: si las restricciones están activas y has seguido los pasos una sola vez, deben aparecer cuatro libros: 101, 102, 103 y 104. Las pruebas B, C y D no deben haber añadido filas.

6. Consultar información de las dos tablas

Hasta ahora hemos consultado cada tabla por separado. Para mostrar el título de cada libro junto al nombre de su estantería, copia y ejecuta:

SELECT Libro.titulo, Estanteria.nombre
FROM Libro
JOIN Estanteria
    ON Libro.id_estanteria = Estanteria.id_estanteria;

JOIN combina información de ambas tablas. En este caso, relaciona cada libro con la estantería cuyo identificador coincide con el que guarda el libro.

El resultado debe contener estos datos, aunque el orden de las filas puede variar:

titulonombre
El universoCiencia
El cuerpo humanoCiencia
Cuentos del bosqueLiteratura
Los planetasCiencia
Observa y responde
  1. ¿Qué dos campos se comparan para relacionar los datos?
  2. ¿Por qué aparece Ciencia junto a tres libros?
  3. Historia no aparece en esta consulta. ¿Significa eso que se ha eliminado la estantería o que no tiene libros relacionados?
