Pantalla 07 · Sintaxis FOREIGN KEY

Escribir la relación

¿Cómo se crea una FOREIGN KEY?

Se declara en la tabla hija: indica qué columna conecta con qué tabla y con qué clave.

07B · Ejercicios de FOREIGN KEY →

La sintaxis general

[CONSTRAINT nombre_restriccion]
FOREIGN KEY (columna_hija)
    REFERENCES tabla_padre(columna_referenciada)

Los corchetes indican una parte opcional y no se escriben. En nuestros ejemplos, la columna referenciada es la clave primaria del padre.

CONSTRAINT

Permite dar un nombre a la restricción: por ejemplo, fk_pedidos_clientes.

FOREIGN KEY

Indica la columna de la tabla hija: pedidos.id_cliente.

REFERENCES

Indica la tabla y clave de destino: clientes(id_cliente).

Paso 01 · Primero el padre

Crear clientes

La clave a la que apuntaremos debe existir.

CREATE TABLE clientes (
  id_cliente INT PRIMARY KEY,
  nombre VARCHAR(100)
);

clientes.id_cliente identifica a cada cliente.

Paso 02 · Después la hija

FK sin nombre explícito

MySQL asigna un nombre a la restricción.

CREATE TABLE pedidos (
  id_pedido INT PRIMARY KEY,
  fecha DATE,
  id_cliente INT,
  FOREIGN KEY (id_cliente)
    REFERENCES
      clientes(id_cliente)
);

La columna id_cliente de pedidos solo puede contener un cliente existente o NULL, porque aquí admite valores nulos.

Alternativa al paso 02

FK con CONSTRAINT

Elegimos el nombre de la restricción.

CREATE TABLE pedidos (
  id_pedido INT PRIMARY KEY,
  fecha DATE,
  id_cliente INT,
  CONSTRAINT
    fk_pedidos_clientes
    FOREIGN KEY (id_cliente)
    REFERENCES
      clientes(id_cliente)
);

La relación es la misma. El nombre fk_pedidos_clientes permite identificar la restricción.

Dos formas de crear la misma tabla hija. Elige el ejemplo 2 o el 3; no ejecutes ambos. Si el cliente es obligatorio, declara id_cliente INT NOT NULL. Usamos tablas InnoDB.
