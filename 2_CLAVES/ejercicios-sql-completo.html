Ejercicio 01

Crea clientes y pedidos

Crea las dos tablas, primero clientes. Sus PK serán autonuméricas y se declararán en columna. Cada pedido tendrá cliente obligatorio. Nombra la FK fk_pedidos_cliente. Impide borrar clientes con pedidos y propaga los cambios de su ID.

clientes

PKid_clienteINT · AUTO_INCREMENT
nombreVARCHAR(100) · NOT NULL
1N

pedidos

PKid_pedidoINT · AUTO_INCREMENT
fechaDATE · NOT NULL
FKid_clienteINT · NOT NULL

ON DELETE RESTRICT · ON UPDATE CASCADE

Dos PK autonuméricas en columna · FK con nombre · RESTRICT y CASCADE.
Ver una posible solución
CREATE TABLE clientes (
    id_cliente INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL
);

CREATE TABLE pedidos (
    id_pedido INT AUTO_INCREMENT PRIMARY KEY,
    fecha DATE NOT NULL,
    id_cliente INT NOT NULL,
    CONSTRAINT fk_pedidos_cliente
        FOREIGN KEY (id_cliente)
        REFERENCES clientes(id_cliente)
        ON DELETE RESTRICT
        ON UPDATE CASCADE
);

Ejercicio 02

Conserva las incidencias sin cliente

Crea incidencias y declara su PK como restricción de tabla con CONSTRAINT. Si se borra el cliente, conserva la incidencia con FK a NULL. Si cambia su ID, propágalo.

clientes

PKid_clienteINT
1N

incidencias

PKid_incidenciaINT
descripcionVARCHAR(200)
FKid_clienteINT · admite NULL

ON DELETE SET NULL · ON UPDATE CASCADE

PK de tabla con CONSTRAINT · FK que admite NULL · SET NULL y CASCADE. MySQL llama PRIMARY a la PK aunque escribas pk_incidencias.
Ver una posible solución
CREATE TABLE incidencias (
    id_incidencia INT NOT NULL,
    descripcion VARCHAR(200),
    id_cliente INT NULL,
    CONSTRAINT pk_incidencias
        PRIMARY KEY (id_incidencia),
    CONSTRAINT fk_incidencias_cliente
        FOREIGN KEY (id_cliente)
        REFERENCES clientes(id_cliente)
        ON DELETE SET NULL
        ON UPDATE CASCADE
);

Ejercicio 03

Identifica las líneas con una PK compuesta

Crea lineas_pedido. Cada línea se identifica por id_pedido + num_linea. Si se borra el pedido, borra sus líneas; si cambia su ID, actualiza la FK.

pedidos

PKid_pedidoINT
1N

lineas_pedido

PK + FKid_pedidoINT
PKnum_lineaINT
descripcionVARCHAR(100)

(101, 1) y (101, 2) son dos líneas distintas del mismo pedido.

Una PK de dos columnas · una FK de una columna · CASCADE en ambas acciones.
Ver una posible solución
CREATE TABLE lineas_pedido (
    id_pedido INT NOT NULL,
    num_linea INT NOT NULL,
    descripcion VARCHAR(100),
    CONSTRAINT pk_lineas_pedido
        PRIMARY KEY (id_pedido, num_linea),
    CONSTRAINT fk_lineas_pedido
        FOREIGN KEY (id_pedido)
        REFERENCES pedidos(id_pedido)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);
